# 重启后历史加载失败：本机离线恢复

> **版本边界**：下述七模块计划和端口是当时恢复现场的记录，不是后续版本的通用安装方案。源码再次修改或构建后，必须重新核对源码、安装包及计划哈希；旧计划应拒绝不匹配的模块，不能绕过校验强行套用。后续计量、协议或客户端修复未必包含在这份历史计划中。运行宿主、真实日志迁移和代码构建是三个独立步骤；未执行迁移/重启就不能宣布历史恢复通过。

## 原因与当前状态

这是 Maestro 插件把未标记为可忽略的私有事件写入了会话日志，重启后宿主严格重放拒绝读取；不代表聊天正文全部损坏。不要删除历史目录，也不要关闭宿主的未知事件校验。

本机已完成源码修复和构建：授权凭据仅存在于运行时、用量保留在插件的权威账本及内存显示中；必要的子会话元数据以显式 `ignorable: true` 写入。旧日志只需要给三种已确认的插件事件补兼容标记，不删除事件、不更改正文、时间或序号。

2026-11-01 21:34 的[只读预演](<../session-history-repair-20261101-213421-b276f9a3.json>)：411 份 v4 日志，39 份受影响，共 160 个待补标记，0 份拒绝读取。运行中的旧插件仍可能生成新的受影响日志，因此真正执行时会重新扫描，不能直接复用旧报告。

**截至本次脚本修复，只做了真实数据的只读检查及合成副本测试，没有安装热修复，也没有修改真实会话日志。原 GUI 的重启恢复仍待实际执行后验证。**

## 本次脚本执行失败

已在本机 PowerShell 7 的合成文件中复现：`[IO.File]::Replace($temporary, $entry.Target, $null)` 的第三个参数被 PowerShell 转成空字符串，抛出 `The path is empty. (Parameter 'path')`，导致原子替换失败。不是 ZSTD 解压失败，也不是需要删除历史。

[Windows 入口](<../scripts/apply-session-history-hotfix.ps1>) 已改用 `[NullString]::Value`，向 .NET 传递真正的 null。仍然使用 Windows 原子替换，保留目标元数据；不会降级为删除后复制，也不会原地改写包管理器硬链接的共享内容。

失败现场的七份代码备份 SHA-256 均与计划中的原始哈希一致；第一个模块仍为旧版，新版临时文件仍在，尚未进入日志修复阶段。**保留这些备份和临时文件即可，修正后的入口会复用哈希匹配的代码备份，不需要先删除它们。** 若备份不匹配，仍会拒绝安装。

同时修复了另一个诊断问题：树级日志修复失败时的 JSON 报告通常写入 stderr，入口现在会保存该报告并显示错误代码/阶段，再以失败结束；仅含 `status`/`code` 的参数拒绝报告也不会被 StrictMode 的缺字段错误覆盖。

[Windows 集成测试](<../tests/apply-session-history-hotfix.test.ts>) 使用合成插件目录、合成多帧 ZSTD 日志及临时监听端口，覆盖原子安装、已有备份重试、硬链接、只读预演、源码/目标哈希变化、坏备份、监听端口拒绝和 stderr 报告保存。不对真实安装或历史运行 `-Apply`。

## 执行顺序

1. 先将下面的命令复制到**独立于 DSH 的 PowerShell 窗口**。
2. 保存当前工作，完全退出 DSH 桌面端及其他 DSH/headless 进程。仅关闭浏览器标签页或窗口、让程序留在托盘中，不算退出。不要在 DSH 内部终端执行应用命令。
3. 保持 DSH 关闭，运行：

```powershell
pwsh -NoProfile -Command "& 'D:\github\dsk-plugin\dsh-maestro-codex\scripts\apply-session-history-hotfix.ps1' -Apply -ConfirmDshFullyExited -AdditionalPort 7600,8273 -NodePath 'D:\devlop\node-v24.8.0\node.exe'"
```

本次运行的 GUI 使用 7600，用户原命令还指定了 8273，因此两个端口都追加检查；14983 始终检查，不能用其他端口替换它。若还运行过其他端口的 DSH 服务，必须一并退出并追加相应端口。多个 `int[]` 参数通过 `pwsh -File` 传入不可靠，因此这里使用 `-Command`，在 PowerShell 内解析 `7600,8273` 数组。

端口不通并不证明后台写入进程已停止，完全退出的人工确认仍是必要条件。脚本不会替你停止任何进程。

不带 `-Apply -ConfirmDshFullyExited` 时只验证计划和扫描日志，可以在 DSH 运行时预演：

```powershell
pwsh -NoProfile -Command "& 'D:\github\dsk-plugin\dsh-maestro-codex\scripts\apply-session-history-hotfix.ps1' -AdditionalPort 7600,8273 -NodePath 'D:\devlop\node-v24.8.0\node.exe'"
```

原先只指定一个端口的 `pwsh -NoProfile -File ... -AdditionalPort 8273` 形式仍然可用，但不会额外检查 7600；完全退出当前 DSH 的要求不变。

## 入口做什么

- 校验已准备的 [热修复计划](<../session-history-hotfix-plan-20261101.json>)、插件身份/版本及七个运行时模块的新旧 SHA-256；若代码被再次构建或安装目录被升级而哈希变化，拒绝覆盖，需先重新核对。本次仅修正脚本，不需要重新构建插件或重新生成计划。
- 只更新桌面 profile 中的七个宿主运行时 JavaScript 模块，不替换其他源码、插件配置或客户端包。每个模块在同目录留下带原 SHA 的 `.maestro-history-original-….bak` 备份；全部代码备份校验完成后才开始逐文件原子替换。已符合目标哈希的模块不重复替换，已有且哈希匹配的代码备份不重复覆盖。
- 从本次扫描建立全新的日志计划。若遇到坏日志、链接或扫描拒绝，整个日志批次在写入前停止。
- 每份待修日志先创建带原 SHA 的 `.maestro-original-….bak` 原始字节备份并验证，再写入并校验。日志备份与代码备份策略不同：不会覆盖或直接复用已有日志备份；碰撞时停止并要求检查。不会删除聊天或插件的权威用量账本。
- 只给 `maestro/cli-access`、`maestro/cli-usage`、`maestro/cli-child` 补 `ignorable: true`；其余未知必需事件不会被擅自忽略。保留原始 JSON 字节内容；未改动的 ZSTD 帧保持原样。
- 修后逐份复读，验证目标哈希与 `changed: 0`。成功或日志阶段失败报告写到工作区中带时间戳的 JSON 文件，终端显示路径和摘要；报告不包含聊天正文或授权 token。
- 不自动关闭、启动或重启 DSH。

## 成功后验证

只有命令成功结束后，才手动启动 DSH，并刷新实际使用的原 GUI（本次会话为 [7600](<http://127.0.0.1:7600>)；若使用另一宿主，则刷新它原来的地址，例如 [8273](<http://127.0.0.1:8273>)）。不要为此另起替代服务。

1. 打开原故障会话 `session-1e1ac3fa-ae8b-4c3e-88ad-0c7a667595dc`，检查历史正文是否完整。
2. 再检查其他受影响会话。
3. 新建普通会话，再正常退出并重启 DSH，确认新历史仍可加载。
4. 检查 CLI 授权、子会话目录与用量显示。用量的 canonical 文件没有被这次恢复删除；同一 usageId 的旧事件与账本若值冲突，显示层目前仍是先到先得，本修复不做历史账务纠错。

**源码测试、只读预演和 `changed: 0` 不等于宿主完整重放验收。** 若仍报其他未知事件类型，保留报错，不要扩大忽略范围或删除日志。

## 失败或部分成功

这是逐文件恢复，不是整个插件加全部日志的事务。任何一步失败都会停止；已经成功的文件不自动回滚。日志修复 API 报错时，当前文件也可能已经有备份或已完成替换，需要根据报告中的路径和哈希检查。

- 本次已确认是第一个代码模块原子替换失败，全部代码备份匹配且尚未开始修日志：保留原备份和临时文件，完全退出 DSH 后可按上面的修正命令重试；入口仍会重新校验当前文件。
- 如果出现日志阶段错误、`BACKUP_ALREADY_EXISTS`、部分成功或其他未定位失败：保持 DSH 关闭，保留所有原始备份、失败报告及可能残留的临时文件，将终端报错和报告路径交给维护者。不要盲目重跑、手动删备份、恢复旧插件后继续使用，或对仍有写入进程的日志做替换。

备份包含完整历史敏感内容，应维持用户目录的访问保护，不要上传到公共仓库。
